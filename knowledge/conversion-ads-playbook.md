## 1. 目的と見るべき指標

コンバージョン広告の目的: メールアドレス / 公式LINEの登録、商品・サービスの申し込み、
店舗への予約。

見るべき指標: **CV数 / CPA / CVR（成約率）/ バックエンドへの誘導率 / CPO**。

広告種別で見る指標を分けること。認知広告に CTR や CPA の改善を求めない
（認知は完全視聴率と配信面だけ）。逆に CV 広告は視聴率ではなくこの指標群で判断する。

## 2. 判断基準の優先順位（最重要）

広告の良し悪しは以下の優先順位で判断する。**上位の指標が悪ければ、下位の指標が
どれだけ良くても広告を止める。**

1. **バックエンドが売れているか / CPO / ROAS**
2. **セミナー・説明会に申し込みが入っているか**（リスト比の申し込み率）
3. **CV しているか・登録の成約率（CVR）/ CPA**
4. CTR（クリック率）/ CPC（クリック単価）
5. CPM（配信単価）

- CPO（Cost Per Order）= 広告費 ÷ 販売本数。例: 100万円で5本売れたら CPO 20万円。必ず算出する。
- ROAS = 売上 ÷ 広告費 × 100。**合格ライン 300%**（広告費以外の経費を考えると
  3倍の売上がないと利益が残らない）。
- **ROAS が良ければ CPA が高くても OK**。例: CPA 1万円でもセミナー申し込み率10%なら合格。
  逆に CPA 500円で日100リスト入ってもセミナー申し込みゼロなら典型的なダメ広告。
- **限界CPA**: 広告費が高騰しても ROAS 300% を下回らない CPA を上限として設定し、
  そこまでは攻める。

## 3. 最初の見切りライン・ダメな広告の定義

- **1,000リーチに達して CV が 0 件なら見切る**（最初の判断基準）。1,000人が見て
  1件も CV しない広告はダメ。CTR がどれだけ良くても止める。
- **ダメな広告の定義: リーチ1,000超えでリンククリック CTR が 1% を下回る**。
- CV 広告のフリークエンシーは 2 前後が目安。2 を大きく超えると飽きられる
  （認知広告は高くても OK — 別プレイブック参照）。

## 4. ファネル基準値（売上から逆算する）

広告費から考えるのではなく、**売上目標から全部逆算する**。

| 項目 | 基準値 |
|---|---|
| オプトインLPの登録率（アクセス比） | **20%** が合格ライン |
| セミナー・説明会の申し込み率（獲得リスト比） | **5%** が最低ライン |
| セミナー成約率 | 最低 **20%** |
| 個別相談の成約率 | 最低 **40%** |
| 講座など役務提供の単価 | **30万円以上**を推奨（サポート有無・期間で単価は変わる） |

逆算例: 売上1,000万円 = 単価50万円 × 20件 ← セミナー成約率20%で100人集客
← 申し込み率5%で2,000リスト ← CPA 2,000円 → 広告費400万円。

基準値を下回った場合の見立て:
- LP登録率 20% 未満 → 広告の訴求とオプトインLPの整合性がズレている。
- セミナー申し込み率 5% 未満 → オプトとセミナーLPの整合性ズレ、または広告の訴求で
  求めていない客層が来ている。

## 5. 整合性（メッセージマッチ）と訴求ワード

- **広告で言っていることと LP で言っていることを一致させる**。広告「インスタ集客」→
  LP「リール集客術」のようなズレは登録率を直撃する。
- 冒頭の訴求から最後のオファーまでの**一貫性**を保つ。数値が悪化してきたら、
  まず冒頭訴求とオファーの一貫性が崩れていないかをチェックする。
- **訴求ワードで集まる客の質が決まる**。「お宝キーワード」= 自己投資欲のある人が
  反応する言葉（例: すでに広告で集客できていて、さらに伸ばしたい人向けの文言）を使う。
  「簡単・手軽」「クーポン」訴求は行動しない・支払い能力の低い客を集める。
  同一商品でも集め方だけで売上が1,000万円以上変わった実例あり。

## 6. 配信面・配信設定

- **配信面チェック**: 広告マネージャーの「内訳 → 配置」でどの面に出ているか確認する。
  **オーディエンスネットワークへの配信が20%を超えていたら危険**（アプリ内強制視聴
  広告枠で、CV する見込みのないトラフィック）。
- **バリュールールで抑制**: 配置チェックを外すと ASC（AI配信）が解除されてしまうため、
  外すのではなくバリュールールでオーディエンスネットワークへの入札を **-90%**（最大）
  に減額する。性別・年齢・デバイスも調整可能（減額は最大-90%、増額は最大+1000%）。
  1つのバリュールールに設定できる条件は2つまで、ルール自体は複数作成可。
  作成後に「ルールセットを適用」へのチェックを忘れると反映されない。
- **ASC と A+A（Advantage+オーディエンス）は必ず両方配信**。A+A は ASC の配信データの
  一部を使う（Meta公式）ため相乗効果がある。予算比率（5:5 / 4:6 / 6:4…）の
  ゴールデンルールは案件ごとにテストで見つける。**判断はキャンペーン単位ではなく
  広告アカウント単位の CPA** で行う（チームプレイなので片方だけ切らない）。
- **既存顧客の除外**: メルマガリスト等をカスタムオーディエンス化し「既存顧客」に設定、
  「既存顧客の予算上限」を 0% にして初めて除外される。
- **ピクセル**: 広告で使う全ページに設置。登録完了ページに CompleteRegistration、
  購入完了に Purchase（通貨は USD→JPY に変更）。ポータルサイト（ホットペッパー等）に
  飛ばすと計測不能。
- 認知広告は日予算500円でいいので**常に出稿しておく**のが理想（CV広告が
  「はじめまして」にならないため）。

## 7. 運用ルーティン

- **朝一ルーティン**: PC を立ち上げたら必ず広告マネージャーを開き、CPA / CTR / CV数を
  毎朝チェックする（ブックマーク登録推奨）。
- **運用基準を事前に決める**: 限界CPA、リーチ数と CTR、説明会申し込み率。
  迷ったら §2 の優先順位表に当てはめる。
- 内製化は極力2人体制が理想。代理店と併用する場合は予算を分け、オーディエンスが
  カニバらない（重複しない）ように分けて運用する。

## 8. CV 動画クリエイティブ

- **認知用とCV用の動画は別物として作る**（認知用動画をCV広告に流用すると
  リードは取れても質が合わない事故が起きる）。
- **お客様の声の必須4項目**（感想は不可・具体的な数字で）:
  1. サービス利用前の悩み（具体的に）
  2. 利用後の成果（「〜な気がします」等の感想は NG。具体的な数字）
  3. 利用を決めた決め手
  4. まだ利用していない方へのメッセージ
  （可能なら「記憶に残っているエピソード」も。動画で、できれば対面で収録。
  お客様の声だけ見て成約する人がいるほど破壊力がある。）
- **動画構成**（6年間不変の型）: 最もインパクトのある実績のアイキャッチ →
  本編動画 → お客様の実績アイキャッチ（できれば2名分）→ 本編 →
  ノウハウ（結論を先に、理由を後に）→ 2本目動画のアイキャッチ（約1分以上）→ オファー。

## 9. VSL ファネル（CV広告の受け皿）

- **動画埋め込み型LP（推奨）**: LP内の動画（12〜15分・1.2倍速）を5分視聴すると
  登録フォームが出現する方式。登録前から教育されるため質が極めて高い
  （実績: 登録220件で申込31件・バックエンド成約率14%・登録特典ゼロで可）。
  デメリット: 登録率が下がり CPA は高騰する（5,000円〜1万円超もあり得るが質で回収）。
  登録前動画の構成: 常識の破壊 → 悩み → 新手法の提示 → 実績 → ベネフィット。
- **従来のオプトイン型VSL**: 登録後に動画で教育・販売。10万円以下の低価格帯向け。
  質は下がる。
- **オファーは早く**。ステップ配信が終わったら即オファー（翌日夜でもいい）。
  1〜2ヶ月後では登録したことすら忘れられている（人は寝たら約4割忘れる）。

## 10. AdDroid 適用時の要点

- 自動化ルール（毎時・承認制）: `pause-cv0-after-1000reach`（1,000リーチCV0で停止提案）
  と `pause-low-ctr-ads`（リーチ超過&CTR1%未満で停止提案)。いずれも
  `campaignObjectiveExcludes: [OUTCOME_AWARENESS]` で認知広告を除外している
  （認知は CV=0 が正常）。
- reach は Meta insights の impressions ÷ frequency で導出。frequency 未取得時は
  impressions ≥ 1,500 で代替判定。
- AI 改善提案（improvement_pr）には本プレイブックの判断基準が knowledgeBriefs として
  注入される。閾値の変更は `workflows/conversion-playbook.yaml` を編集する。
